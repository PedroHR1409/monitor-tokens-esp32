## Summary

As sessões OpenCode passaram a exibir o estado REAL: `ask` (tool `question` aberta,
nos estados pending/running), `perm` (via log do OpenCode — `action.action=ask` — com
frescor de 10 min e invalidação por atividade posterior), `work`/`free` pelo ciclo do
turno (último part), e contexto por modelo (GLM ~1M validado contra a UI do OpenCode).

## Lessons Learned

### Process
- Cada correção foi validada ao vivo contra o OpenCode antes da próxima — os 3
  falsos positivos/negativos só apareceram com dados reais.
### Technical
- Partes do OpenCode são atualizadas IN-PLACE: estado real = maior time_updated.
- `pending` de tool é pipeline (nasce pending, vira running em segundos).
- A pergunta aberta fica `pending` OU `running` — cobrir os dois estados.
- Janela de contexto do modelo não se assume: validar contra a UI (584k = 58%).
